Enrollment no longer asks the user to commit by hand. Before the Enrollment binding is prepared, when a dirty file inside the task `scope_hint` or an untracked TaskIntent would fail Enrollment, the Host silently commits those paths together with the task's own TaskIntent and the Spec its binding names, as one commit with the subject `chore(imm): commit Enrollment preconditions for <task-id>`, on Claude Code and Pi. The native confirmation binds the resulting HEAD. A TaskIntent that is only staged over a clean scope makes no commit, and dirty paths outside the set are neither committed nor blocking. The commit uses an explicit literal path list and runs Git hooks normally; a refused commit fails Enrollment with Git's message. With an unborn HEAD the empty root commit still comes first, and a TaskIntent or owner changed while the following commit runs is refused. An Enrollment that an existing owner would refuse commits nothing. If Enrollment is declined, cancelled or fails after the commit, the result names the commit that remains. The Kernel still refuses a dirty scope that reaches it directly, and that refusal no longer tells the user to commit. ADR 0023 records the decision and the accepted risk that unfinished work inside the scope is committed without being shown first (#231).
