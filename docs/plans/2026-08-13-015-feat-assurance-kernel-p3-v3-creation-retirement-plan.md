## Goal

Retire acquisition of new v3 managed-task authority in this project after a host-neutral Kernel TaskIntent planning route exists, while preserving the Pi TUI boundary as the sole enrollment authority, pre-existing v3 drain behavior, and read-only legacy projection.

## Task

Implement the P3 executable slice: (1) add a Git-owned managed-task routing policy parser/status projection and enforce its v3 new-Plan guard before automatic migration or any state preparation, (2) add one host-neutral Kernel TaskIntent authoring-validation contract while preserving the Pi TUI boundary as the sole enrollment authority, and (3) activate the exact reviewed policy bytes, verify legacy closure/projection behavior, and record the explicit no-terminal-import decision.

## Output Language

Spec and Plan prose use English. Schema fields, CLI commands, file paths, JSON keys, enum values, Step IDs, and contract identifiers remain literal.

## Origin

P2C closed with Pi as the only qualified Kernel host and made `/imm-canary-new` the default enrollment route, while explicitly deferring P3. Audit of that route found it never authors a TaskIntent and requires an existing Git-tracked `docs/plans/<task-id>.intent.json`; no supported Planner/CLI authoring-validation path exists. P3 therefore cannot safely stop v3 Plan creation until that planning gap closes. The parent P2 cutover contract requires P3 to stop v3 new-task creation, retain read-only v3 projection, and make an explicit terminal-import decision.

## Research

- `plugins/immune-brain/runtime/kernel/intent.ts` already owns strict `task_intent/v1` parsing, canonical content hashes, secure Git-owned descriptor reads, task/path identity, size bounds, symlink rejection, and read-time identity re-verification. P3 should reuse these primitives instead of introducing a second intent schema.
- `plugins/immune-brain/.pi-extension/pi-canary-verification.ts` currently owns `verification_descriptor/v1` parsing. P3 must extract its accepted syntax into one host-neutral pure module without tightening the existing wire contract; Pi assurance keeps runner resolution/execution and consumes the shared parser.
- `/imm-canary-new` and `/imm-canary-enroll` intentionally never author TaskIntents. Both require the TaskIntent to exist and be Git-tracked before preparation, then preserve same-lock secure reread and P2 authority boundaries. Pi TUI is the sole enrollment boundary: `/imm-canary-new` is the default no-waiver route, while `/imm-canary-enroll` is the existing literal-user-confirmed waiver route.
- `plugins/immune-brain/runtime/commands/kernel.ts` appends a friction-journal entry for every current Kernel command. The new Intent author/validate commands require explicit no-journal dispatch; author performs only exclusive draft creation, while validate is zero-write. Existing status/readiness/journal/migrate behavior must stay unchanged.
- `plugins/immune-brain/runtime/immune_brain_runtime.ts` calls `prepareProjectAccess` before `commands/plan.ts`; a guard only inside `runPlanCommand` is too late because write access may automatically migrate legacy state first. Retirement policy preflight must occur in canonical dispatch before project access preparation.
- `plugins/immune-brain/runtime/commands/plan.ts` owns the single v3 Plan sync mutation boundary, including initial sync, ordinary switch, and approved successor transitions. Validation-only output is already separate from `--sync`.
- v3 execution, QA/review, finish, termination, projection, and format migration are separate commands over an already-synced Plan. A creation policy at the sync boundary can preserve these without a compatibility adapter.
- Host identity is not a trusted CLI or Skill input. TaskIntent authoring-validation is therefore host-neutral; Pi gets the sole supported enrollment authority, while other hosts can plan and review but cannot start Kernel managed execution.
- Existing project-local `config.toml` files are agent-native and not a shared Git authority. The retirement decision needs one project-owned versioned JSON contract.
- Retained v3 Plans, Specs, Ledger history, authority receipts, and automatic observations already satisfy historical projection/audit consumers. No concrete consumer requires synthetic terminal TaskRecords.

## Decisions

1. Add strict `docs/plans/managed-task-routing-policy.json` parsing and the read-only `imm-plan --routing-status --json` projection. A path absent from both worktree and index means `legacy_v3`; every present invalid/untracked/tracked-deleted/drifted state blocks new authority; only identical strict bytes in worktree and Git index activate the route. The runtime never stages or commits policy bytes.
2. Move v3 sync policy preflight into canonical dispatch before `prepareProjectAccess`. Enforce `v3_new_plan_sync: retired` at every different-identity `imm-plan --sync` path before migration, locks, journals, receipts, observations, or temporary files. Preserve current-format same-identity access for the already-synced P3 Plan and preserve all non-sync operations over pre-existing authority: activation, execution evidence, QA/review, termination, finish, validation-only reads, migration, and projections.
3. Add `imm-kernel intent author <intent-path> --stdin --json` and `imm-kernel intent validate <intent-path> --json` as canonical no-migration, no-journal commands. Author requires the active `kernel_task_intent` route, rejects active ownership, canonicalizes the strict candidate through `parseTaskIntentV1` plus the shared verification parser, and exclusively creates one new untracked draft without staging, enrollment, workflow-state writes, parent creation, or overwrite. Validate remains completely zero-write and reports `valid` independently from `enrollment_ready`.
4. Extend `imm-planner` with host-neutral deterministic backend routing. Under a valid `kernel_task_intent` policy it sends exactly one complete candidate to `imm-kernel intent author`, then validates the created artifact; active Kernel/v3 ownership routes back to the owning workflow; missing policy preserves legacy compatibility; invalid policy rejects with no v3 fallback. Planner never writes an Intent directly, enrolls a task, writes runtime state, stages Git, or overwrites an existing Intent.
5. Preserve Pi TUI as the sole production enrollment boundary, with exact packaged commands `/imm-canary-new` (default, no waiver) and `/imm-canary-enroll` (explicit literal-user-confirmed waiver). No CLI, Skill, OpenCode/RPC/JSON/print surface, environment value, or host assertion can mint enrollment authority.
6. Install this repository's policy only in the final Step after the guards and Kernel planning route are verified. The exact bytes have SHA-256 `43949f0ef456efb9ca7dccbe1c8bc2355d6acce66486213fb2750a87388ec71e`; the Step executor stages only this path and proves index/worktree byte identity before activation.
7. Do not implement terminal v3 import. Reconsider only in a separate Plan naming a concrete consumer that cannot use retained projection and proving all Kernel invariants without fabrication. Owner: user.
8. Retained v3 drain/read-only code is permanent until a separate v4-only storage-retirement Plan proves there is no nonterminal v3 ownership and all audit/projection consumers have replacements. Owner: user; cleanup milestone: that Plan's completion.

## Assumptions

- P3 is synced into the State Ledger before Step 3 installs the retirement policy. Step 1 still proves current-format same-identity access; legacy-format state never earns that exception.
- TaskIntent authoring-validation is host-neutral. Pi remains the only privileged enrollment host; no host flag, environment variable, serialized caller assertion, or agent-local config qualifies another host.
- The authoring command is the sole draft writer: it accepts bounded stdin, requires the active Kernel planning route, canonicalizes accepted bytes, uses exclusive no-overwrite creation, and never creates parent directories, stages Git, or writes workflow state. The Planner does not write the file directly.
- The shared verification parser preserves existing Pi syntax: JSON whitespace/order and contained repository-relative `cwd` remain accepted. Planner emits canonical bytes, and enrollment readiness still requires exact frozen Bun runner compatibility.
- Git may be unavailable for draft validation, but enrollment readiness remains false unless tracked ownership is positively proven.
- The Step 3 executor may update the Git index for only `docs/plans/managed-task-routing-policy.json`; no runtime command, Skill, or validator may stage or commit files.
- Direct Path continues to be governed by the existing Workflow Activation gate and does not use `imm-plan --sync`.

## Current-Slice Warning

This Plan retires new v3 authority acquisition only in projects that explicitly install the policy. It does not delete v3, migrate active/terminal Plans, qualify another enrollment host, synthesize TaskRecords, change Direct Path, or provide a fallback when Kernel planning/enrollment is blocked.

## Plan Boundary

One coherent P3 slice first installs the guard while policy is absent, then makes the host-neutral Kernel planning route usable, then activates exact policy bytes only after both are verified. This order prevents pre-migration bypass and self-lock; splitting Intent planning into a later Plan would strand new managed work after retirement.

## Boundary Rationale

The policy parser, canonical pre-dispatch guard, and routing status are one authority boundary: a guard inside `commands/plan.ts` is too late because automatic migration runs first, while a policy with no guard is advisory. TaskIntent authoring-validation is a separate closeable invariant over host-neutral planning bytes; privileged enrollment remains unchanged and Pi-owned. Final policy activation is isolated so the first two Steps execute under existing v3 ownership and every active byte is content-bound before the irreversible project transition.

## Scope Pressure

The slice spans canonical pre-migration routing, Git index/worktree identity, a host-neutral Intent write/read boundary, Pi verification-parser consumers, packaged Planner contracts, and v3 closure. Retain three sequential Steps because policy activation is unsafe before both the guard and replacement planning route are closed, while splitting those prerequisites into later Plans would either expose a bypass window or strand new managed work. The broad U2 file set is one parser/authoring contract with one rollback; it must not expand into enrollment authority or general workflow-state mutation.

## Devil's Advocate Audit

- **Rollback resilience**: U1 is dormant while policy is absent and rolls back with its parser/router/tests. U2 creates drafts only in isolated fixtures until U3 and rolls back with the shared parser, canonical command surface, Planner contract, and tests; no TaskRecord or claim exists to migrate. U3 is the explicit project transition: if interrupted, exact staged policy bytes keep new v3 sync retired while the already-owned P3 Plan remains work/review/finish-capable. Re-enabling v3 requires a separately reviewed policy revision, never an ad hoc edit or fallback.
- **Verification vanity**: File-existence checks are only prerequisites. Focused tests must fail on pre-migration writes, same/different identity confusion, policy index/worktree drift, stdin overread or accidental stdin reads by other commands, non-canonical author output, overwrite/symlink races, parser divergence, alternate enrollment surfaces, and canonical `imm-finish` self-lock. U3 additionally binds exact bytes to a fixed hash in both worktree and index.
- **Spec dilution detection**: P3 still delivers all three parent obligations: stop new v3 authority, retain legacy drain/read-only projection, and decide terminal import. The replacement TaskIntent planning path is executable rather than prose-only, but privileged enrollment remains Pi-only. No requirement is narrowed into deleting legacy data, fabricating terminal TaskRecords, or trusting another host.
