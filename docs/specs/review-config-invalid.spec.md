# Review Preparation Reports an Invalid `agents` Configuration (#455)

- **Task ID**: `review-config-invalid`
- **Source**: GitHub Issue #455 (Brainstorm manifest in the `clarify` handoff of 2026-11-16)
- **Design risk**: Medium — additive change to the `ReviewPreparationError` code union and to the `review_ready` coordinator result (an internal machine contract read by every Host), single module family (`runtime/assurance`).
- **Threat model and supported environment**: None beyond the repository's own tooling. Input is the local user/project Immune-Brain configuration the user owns; no adversary. Supported platforms are those of the existing runtime (macOS, Linux).
- **Design views**: service/component interfaces.
- **Output language**: English.

## 1. Problem and evidence

After S1 of `loop-agent-scheduling` (#514, closed 2026-11-16), Review resolves its profile from `agentRole(resolveConfig(root).agents, "code-review")` (`plugins/immune-brain/runtime/assurance/cli_review.ts:173`). Any error in the user `agents` table sets `agents.valid = false` and falls the whole section back to the legacy `lanes` mapping, else to unset (`plugins/immune-brain/runtime/config/agent_roles.ts:222-235`). The errors reach `resolveConfig(root).diagnostics` with `file` and `key_path` (`plugins/immune-brain/runtime/config/layered_config.ts:314`).

1. No legacy profile: `prepareReview` throws `review_profile_required` (`cli_review.ts:399-400`) whose recovery names the deprecated `lanes.review_host` (`cli_review.ts:35-36`); the real cause is not carried.
2. Legacy `lanes.review_*` present: Review runs on it silently; the `review_ready` result (`plugins/immune-brain/runtime/assurance/coordinator.ts:535,1770,2169`) has no warning.
3. `review_host_unavailable` recovery names `lanes.review_host` (`cli_review.ts:102-104`).
4. Docs say an invalid section keeps `review_profile_required` (`docs/reference/immune-brain-config.md:140-143`, mirrored at `plugins/immune-brain/dist/docs/reference/immune-brain-config.md`) and that `review_profile_required` means no `lanes.review_host` resolves (`plugins/immune-brain/dist/drive.md:170-172`).

## 2. Decisions

- **D1 — New code `review_config_invalid`** *(Source: BR-REQ-1)*. In `prepareReview`, when no request/batch profile exists, the `code-review` role is unresolved, and `resolveConfig(root).agents.valid === false`, throw `ReviewPreparationError("review_config_invalid", ...)`. The message names every error-severity diagnostic whose `key_path` lies under an `agents` table (`agents`, `agents.*`, `projects.<key>.agents*`) as `<file>: <key_path> (<message>)`; the recovery says to fix that value in that file, then call `advance_assurance`. The code joins the union at `plugins/immune-brain/runtime/assurance/host_port.ts:75`; `reviewDispatchFailure` (`coordinator.ts:500-502`) already forwards any code, so no consumer branches on the value.
- **D2 — Unset stays `review_profile_required`** *(Source: BR-DEC-3)*. A valid `agents` section (or none) with no `code-review` binding keeps `review_profile_required`.
- **D3 — Recovery text** *(Source: BR-REQ-2)*. `REVIEW_PROFILE_RECOVERY` and the `review_host_unavailable` recovery name `agents.profiles` / `agents.presets` in the user config, not `lanes.review_host`.
- **D4 — Legacy-fallback warning** *(Source: BR-REQ-3, BR-DEC-2)*. When the round's profile came from `resolveReviewProfile` (not a request or Lane batch profile) and `agents.valid === false` with `agents.source.value === "legacy"`, `prepareReview` proceeds unchanged and adds `warnings: [{ code: "review_legacy_profile", paths: [<agents error files>], message }]` to its `HostReviewReservation`; the message states that Review uses the legacy `lanes` profile because the `agents` configuration is invalid and names the first error key path. `reviewReadyDispatch` (`coordinator.ts:493-498`) copies `warnings` onto `review_ready`, so both the fresh (`:1770`) and the replayed (`:2169`) result carry it. The entry shape matches `StatusProjectionWarning`. Optional and additive; absent when there is nothing to warn about.
- **D5 — `prepareVerification` unchanged except D3** *(Source: BR-DEC-1; `cli_review.ts:332-338` reuses the Review reservation's profile and never resolves `code-review`)*.
- **D6 — Docs follow** *(Source: BR-REQ-4)*. Update `plugins/immune-brain/dist/drive.md` (review preparation failure paragraph), `docs/reference/immune-brain-config.md` and its byte-identical mirror (`scripts/dist-sync-manifest.ts:32`). Antigravity mirrors and both MCP bundles are regenerated by `scripts/build-claude-plugin.ts` and `scripts/build-antigravity-plugin.ts` (`docs/agents/derived-files.json`), never hand-edited.
- **D7 — Out of scope** *(Source: BR-OUT-1..4)*. D1 fallback rule of `loop-agent-scheduling` unchanged; valid-profile and unset behavior unchanged; non-`ReviewPreparationError` failures (`review_profile_ambiguous`) unchanged; #501 untouched.

## 3. Component interface

| Surface | Input | Output / error | Compatibility |

| `ReviewPreparationError.code` | — | adds `"review_config_invalid"` | additive; existing codes keep meaning |

## 5. Acceptance and agreed seams

Seam for A1–A3: `tests/cli-review-dispatch.test.ts`, driving `kernel.coordinator.advance` end to end with the existing `reviewRepo` / `homeAgents` helpers (prior art: `describe("review profile required")` at :544 and the S1-AC3 test at :634). This is the highest observable seam: it fails if the code, the forwarding, or the warning copy regresses.

- **RCI-A1** (BR-REQ-1, BR-SCN-1): user `agents` with `profiles.review.host: "codex"` and no project `lanes` → `review_preparation_failed`, `code: "review_config_invalid"`, `reason` contains the user config path and `agents.profiles.review.host`, `recovery_action` contains `agents.profiles.review.host` and `advance_assurance`, QA settlement retained. Negative control: the same table made valid reaches `review_ready`.
- **RCI-A2** (BR-REQ-3, BR-SCN-2): the same invalid table plus project `lanes.review_host: "pi"` → `review_ready` on host `pi` with one `warnings` entry `code: "review_legacy_profile"` whose message names `lanes` and `agents`. Negative control: a valid `agents` table (S1-AC3 shape) yields `review_ready` without `warnings`; legacy-only config (no `agents` table) yields no warning.
- **RCI-A3** (BR-REQ-2, BR-DEC-3, BR-REQ-5): genuinely unset config → `review_profile_required`, recovery contains `agents.profiles` and not `lanes.review_host`; the `review_host_unavailable` case's recovery contains `agents.profiles` and not `lanes.review_host`. Existing assertions at :549 and :771 are updated, not duplicated.
- **RCI-A4** (BR-REQ-4): `plugins/immune-brain/dist/drive.md` and `docs/reference/immune-brain-config.md` name `review_config_invalid`, neither says an invalid `agents` section keeps `review_profile_required`, and `bun scripts/sync-dist-docs.ts --check` passes (mirror byte-identical).
- **RCI-A5**: `bun run typecheck` passes (union and optional fields consistent across Hosts).

Done looks like: a user with a mistyped `agents` host sees the exact file and key to fix; a user on the legacy fallback sees a warning in `review_ready`; nobody is told to set `lanes.review_host`.

## 7. Devil's Advocate Audit

- *Rollback resilience*: all changes are additive fields plus text; reverting the commit restores the old code path with no persisted state touched. A partial implementation that adds the code but not the warning still fails RCI-A2, so it cannot settle.
- *Verification vanity*: RCI-A1/A2 assert through `coordinator.advance`, not `prepareReview` directly, so a missing forward in `reviewReadyDispatch` or a wrong code fails them; negative controls prove the warning is not emitted unconditionally and that the valid path is unchanged.
- *Spec dilution*: every BR item maps in the trace below; the doc requirement has its own acceptance (RCI-A4) instead of riding on code tests.
