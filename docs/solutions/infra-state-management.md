# Pattern: 上下文脱水与重构 (Dehydration & Rehydration)

**领域**: 系统架构 / 状态管理  
**描述**: 解决长对话 Agent 在 Token 溢出或环境切换时的“记忆丢失”问题。

## 场景
- 当任务跨越多个会话时。
- 当环境需要重置但逻辑进度需要保留时。

## 方案模板
1. **脱水 (Dehydrate)**: 将关键变量（摘要、待办事项、逻辑快照）写入持久化 JSON。
2. **重构 (Rehydrate)**: 在新会话开始时，通过脚本读取 JSON 并以结构化 Markdown 形式输出给 Agent。

## 约束与建议
- **同步性**: 脱水时应同时更新人类可读的摘要文件，保持信息对称。
- **原子化**: 状态文件应尽可能轻量，仅保留核心逻辑节点。
- **容错**: 必须处理状态文件缺失或损坏的情况。
